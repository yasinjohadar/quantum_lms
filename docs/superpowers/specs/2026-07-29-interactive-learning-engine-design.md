# Interactive Learning Engine — Design Spec / ADR

**Date:** 2026-07-29  
**Status:** Accepted  
**Product name:** Interactive Learning Engine  
**Scope:** MVP (Phase 1)

## 1. Context

Quantum LMS already has a traditional quiz system (`Quiz`, `Question`, `QuizAttempt`) and AI question-bank generation. This project adds a **separate** Interactive Learning Engine that runs Schema-driven learning sessions inside a Vite runtime — not HTML pages generated by AI, and not an extension of the existing quiz tables.

## 2. Decision

Build an isolated domain:

| Layer | Responsibility |
|-------|----------------|
| Laravel (`app/InteractiveLearning/`) | Authoring CRUD, permissions, Schema storage, attempts API, attachables |
| Vite engine (`resources/js/interactive-engine/`) | Session, modules, theme, animation, audio, result submission |
| AI | Schema **patches** only (`operations[]`) → human Review → Apply. Never emits HTML/JS |

**Rejected alternatives:**

- AI generates full HTML pages each time
- Store experiences inside `quizzes` / `questions`
- Inject AI-authored JavaScript into the runtime

## 3. Goals (MVP)

- Reusable Learning Objects (`learning_experiences`)
- Multi-question sessions with mixed types
- Five **reference** question modules: `true_false`, `single_choice`, `multiple_choice`, `drag_drop`, `matching`
- Registry + Module contract so new types do not touch Core
- Play URL: `/learning-experiences/{id}`
- Result JSON posted to Laravel
- Manual authoring + Improve with AI (patch flow)
- Full AI session generation: designed, feature-flagged **off**
- Lesson attach: table ready; UI later

## 4. Architecture

```
Admin Builder → Schema Builder Validation → learning_experiences
       ↑                                         │
  AI Patch → Review → Apply                      ▼
                                         Play blade + Vite Engine
                                         Session → Registry → Modules
                                         Result Engine → POST attempts
```

**Engine layers (one-way):** Core → Session → Registry/Modules → UI/Theme/Animation/Audio → Result/API

## 6. Data model

### 6.1 Status state machine

`draft` → `review` → `published` → `archived` (also allow archive from draft/review; republish rules as needed).

### 6.2 Tables

**`learning_experiences`**

- `id`, `title`, `description` (nullable)
- `status` (enum string)
- `schema_json` (JSON)
- `schema_version` (string, e.g. `1.0`)
- `engine_version` (string, e.g. `1.0`)
- `created_by` (FK users)
- timestamps

**`learning_experience_attempts`**

- `learning_experience_id`, `user_id`
- `score`, `total`, `percentage`, `duration`
- `started_at`, `finished_at`
- `answers_json`, `result_json`
- timestamps

**`learning_experience_attachables`**

- `learning_experience_id`
- `attachable_type`, `attachable_id` (morph)
- `order` (unsigned int, default 0)
- unique(experience, type, id)

No foreign keys to traditional quiz tables. Deleting a lesson must not cascade-delete experiences.

## 7. Schema / DSL (`version` / `schema_version` = `1.0`)

Root session object:

```json
{
  "version": "1.0",
  "meta": { "title": "", "locale": "ar", "rtl": true },
  "theme": {
    "themeId": "default",
    "accent": "#ea580c",
    "font": "system",
    "density": "comfortable",
    "motion": "full",
    "mode": "system"
  },
  "rules": {
    "allowBack": true,
    "shuffleQuestions": false,
    "maxWrong": null,
    "showExplanation": true,
    "attemptsPerQuestion": 1,
    "timerSeconds": null
  },
  "messages": { "success": [], "error": [], "encourage": [] },
  "questions": []
}
```

### Question node (shared)

- `id`, `type`, `stem`, `points`, `difficulty`
- `hints[]`, `explanation`, `successMessage`, `errorMessage`
- `estimatedSeconds`, `tags[]`, `learningObjectives[]`
- `payload` (type-specific)

### Payload contracts (MVP)

| type | payload |
|------|---------|
| `true_false` | `{ "correct": boolean }` |
| `single_choice` | `{ "options": [{id,label}], "correctId": string }` |
| `multiple_choice` | `{ "options": [{id,label}], "correctIds": string[] }` |
| `drag_drop` | `{ "items": [{id,label}], "zones": [{id,label}], "assignments": {itemId: zoneId} }` |
| `matching` | `{ "left": [{id,label}], "right": [{id,label}], "pairs": {leftId: rightId} }` |

### Validation (three layers)

1. Admin Schema Builder (live)
2. Laravel on save/publish
3. Engine on boot (fail closed)

## 8. Registry metadata

```json
{
  "type": "true_false",
  "name": "صح / خطأ",
  "icon": "check",
  "color": "#4CAF50",
  "category": "basic",
  "editorComponent": "TrueFalseEditor",
  "runtimeModule": "true_false"
}
```

PHP + JS registries must stay in sync for the five reference types.

## 9. Module contract (reference lifecycle)

```ts
interface QuestionModule {
  type: string;
  beforeMount?(ctx): void | Promise<void>;
  mount(el, ctx): void;
  afterMount?(ctx): void | Promise<void>;
  beforeDestroy?(ctx): void;
  destroy(): void;
  getAnswer(): unknown;
  grade(answer): { correct: boolean; score: number; max: number; detail?: unknown };
}
```

All five MVP modules are **reference implementations** of this contract.

## 10. Standard session events

- `session.started`, `session.completed`
- `question.enter`, `question.leave`, `question.correct`, `question.wrong`
- `hint.opened`, `answer.changed`
- `timer.expired`, `result.sent`

Future gamification/analytics subscribe to these events only.

## 12. AI authoring

**Improve with AI (MVP):**

1. Current schema + intent → AI  
2. Response: `{ "operations": [ ... ] }`  
3. Human review (accept/reject/edit)  
4. Apply with undo/redo  
5. Persist schema

**Full session generation:** endpoint + UI behind feature flag; always opens editor; never auto-publishes.

## 13. APIs (MVP)

Admin (auth + admin middleware):

- Resource CRUD `/admin/learning-experiences`
- Status transitions
- `POST .../ai/patch`, `POST .../ai/apply`
- Preview
- `POST .../generate-session` (flagged off)

Play:

- `GET /learning-experiences/{id}` (published; auth student or preview token)
- `POST /learning-experiences/{id}/attempts`

## 14. Engine versioning

- DB columns: `schema_version`, `engine_version`
- Runtime constant `ENGINE_VERSION` must be compatible with stored `schema_version`
- Example: Engine `1.2` can run Schema `1.0` if compatibility map allows

## 15. Out of scope (Phase 2+)

- Merge with traditional question bank
- AI Module Generator for new types
- Lesson attach UI
- Schema copy/versioning product feature
- In-engine gamification (event hooks only in MVP)
- Multiplayer, offline, voice tutor

## 16. Implementation order

1. This ADR (done when file exists)
2. Migrations + models + routes skeleton
3. Schema validator + registries
4. JS Core + Event Bus + Session
5. Admin CRUD + dynamic editors + live validation
6. Play page + attempts API
7. Five reference modules
8. Theme / animation / audio / results polish
9. AI patch review/apply
10. Flagged generate-session stub + empty attachables usage

## 17. Change control

Any future change that breaks Schema `1.0` or Module contract requires:

1. Bump `schema_version` and/or `engine_version`
2. Update this ADR with a dated amendment section
3. Keep old schemas runnable or provide a migration path
